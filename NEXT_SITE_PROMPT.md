# Следующий этап доработки denislesiv.ru

Ты — senior frontend-разработчик и конверсионный копирайтер. Работаешь с Astro-проектом `lesiveducation/denislesiv`, опубликованным через GitHub Pages на `https://denislesiv.ru`. Сохрани текущую структуру, Manrope, палитру `#0c1820 / #14b8a6 / #f2b66d`, спокойный экспертный тон и отсутствие тяжёлых клиентских зависимостей.

Не меняй уже настроенные `site`, корневые пути и `public/CNAME`. Не возвращай `base: /denislesiv`. Не меняй согласованный слоган логотипа `DIGITAL SOLUTIONS / FOR BUSINESS` без отдельного решения пользователя.

## Материалы, которые сначала нужно получить от пользователя

1. Новое hero-фото 4:5 и отдельный квадратный аватар. Требования к сцене согласовать отдельно; сохранить персонажа Сатурна как питомца Codex, если пользователь не решит иначе.
2. Реальные компании и годы для контекста четырёх метрик в блоке опыта.
3. Реальные отзывы с разрешением на публикацию. Не публиковать плейсхолдеры как отзывы.
4. Реальные сведения оператора персональных данных и утверждённые тексты политики/согласия.
5. ID Яндекс Метрики и решение пользователя о модели согласия на cookies.

## После получения материалов

- Подключить новое hero-фото с адаптивными AVIF/WebP-вариантами; сохранить текущую оптимизированную картинку как fallback. Проверить кадрирование на 360, 390, 430, 768, 1024 и 1440 px.
- Решить отдельно, нужен ли мобильный ряд автора с круглым аватаром. Не использовать старое изображение в `#about` автоматически: добавить второе фото только если оно усиливает историю.
- После подтверждения пользователя указать реальные сроки каждой демоверсии в портфолио.
- Добавить контекст к метрикам только после получения проверяемых компаний и периодов.
- Добавить блок отзывов только с настоящими отзывами; компонент может быть скрыт конфигурацией до появления данных.
- Не добавлять искусственный счётчик дефицита. Если ограничение мест реально, использовать проверяемую и обновляемую формулировку.
- Сокращать декоративную типографику выборочно после визуального сравнения, а не удалять всю систему автоматически.
- Добавить обещание о времени ответа только после подтверждения рабочего графика и реальной возможности соблюдать срок.
- Подключить Яндекс Метрику только после получения ID и выбора механизма согласия. Цели: основной CTA, Telegram, бриф и e-mail.
- Подготовить `/privacy` и отдельное согласие на обработку персональных данных на основе реальных реквизитов. Согласие на отправку данных разместить непосредственно в Яндекс Форме. Не публиковать юридические плейсхолдеры.
- Перед включением аналитики и формы проверить локализацию хранения данных и необходимость уведомлений/согласий по действующим требованиям 152-ФЗ; юридические выводы согласовать с профильным специалистом.
- Провести Lighthouse-аудит главной отдельно от страницы с iframe формы. Цели считать ориентиром: Performance ≥ 90, Accessibility ≥ 95, SEO = 100; документировать ограничения сторонних сервисов.
- После настройки DNS проверить apex и `www`, выпуск TLS-сертификата и включить принудительный HTTPS в GitHub Pages. Не сохранять MX Яндекса автоматически: почтовые записи должны соответствовать выбранному почтовому провайдеру.

На выходе предоставить список изменённых файлов, changelog, результаты проверки на контрольных ширинах, Lighthouse-отчёт и перечень оставшихся материалов.
